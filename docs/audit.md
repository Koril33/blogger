# 修复与验证记录

验证日期：2026-10-01。主要改动位于 blogger；blog 增加 27 处草稿标记并修复一处失效的 Java 文档链接；搜索项目只修改页面识别与对应测试。

## 原问题与修复

| 原问题 | 影响 | 新处理 |
| --- | --- | --- |
| 模块导入创建全局进程池、结束后不可重复使用 | Windows 启动开销、导入副作用、同进程二次构建失败 | 局部有限线程池，等待并检查全部任务 |
| 图片 futures 的异常被丢弃 | 损坏图片、附件转换失败被当成成功，站点可能漏资源 | 异常传播，失败不提交输出 |
| 构建开始就删除旧 public | 中途失败导致旧站点消失 | 暂存构建、备份改名、提交失败恢复 |
| 源/输出未校验、路径可穿越、跟随链接 | 递归扫描、误删或发布源目录外内容 | 重叠/所有权检查、链接/junction/特殊文件拒绝 |
| 全部非 Markdown 文件被当作图片转 RGB | PDF/TXT 失败，PNG alpha 丢失，动画破坏 | 资源分类，保守格式处理与普通附件复制 |
| 图片无增量优化 | 每次重编全部图像 | 输入/策略/输出摘要缓存 |
| 简易冒号拆分和不同元数据读取规则 | YAML 引号、多行文本、CRLF/BOM、缺省日期行为错误 | 安全 YAML、一次解析、字段默认值与类型检查 |
| 日期用字符串排序或主机本地 timestamp | 跨时区顺序错误、空/非法日期崩溃 | UTC 时间排序，缺省分组 |
| 分类/归档无自动转义，Windows Path 进入 URL | 元数据 HTML 注入、中文/空格/反斜杠链接错误 | Jinja autoescape、URL 编码与 POSIX 路径 |
| 文章标题忽略元数据 title | 标题与作者元信息不一致 | 三种页面统一使用 metadata.title |
| 非内容文件出现在分类、嵌套/根文章元数据缺失 | 无效链接或归档崩溃 | 明确文章/分类/资源建模，独立 Markdown 页支持 |
| 密码共用，SSH 自动接受未知主机 | 凭据耦合与服务器身份验证薄弱 | SSH/sudo 分开，known_hosts + RejectPolicy |
| 未转义 shell 路径与固定上传名称 | 命令注入、并发覆盖 | 独立上传目录、参数引用、部署锁 |
| 先移动旧站点再解压、无摘要验证 | 失败期间站点不可用，无法区分损坏上传 | SHA-256、安全展开、release 就绪后入口切换 |
| 打包受时间戳、所有者等影响 | 相同站点压缩包不可复现 | 固定顺序/权限/uid/gid/mtime/gzip 时间戳 |
| 刷新接口无超时、错误结果当成功 | 挂起或错误成功提示 | 有界请求，检查 success，独立退出码 3 |
| 三套页面重复模板、依赖 CDN | 布局漂移、网络不可用时样式失效 | 共享模板、本地 CSS/JS、高亮在构建时生成 |
| 搜索按目录布局猜测文章类型 | 带附件的文章遗漏、空分类误收录 | 明确 page marker，旧页保留兼容判断 |
| CLI 缺少必填信息时静默返回 0、坏配置被忽略 | 自动化无法判断失败 | 预检查、明确错误和非零退出码 |

还加入了 Windows 文件扫描器短暂占用的有界改名重试、唯一图片临时文件、构建中源文件变化检测，避免间歇错误、附件重名与不一致缓存。

## 检查结果

- blogger：**67 项通过，2 项跳过**。跳过的是本机不具备 symlink 权限的实机测试；相应切换与恢复场景另在 POSIX 虚拟文件系统中通过。该结果来自本地验证。2026-10-02 按用户要求移除自动 CI 工作流，后续检查由本地手动运行。
- djhx-site-search：**13 项通过**，包括带附件文章、独立 HTML、分类排除和旧页兼容。
- 真实内容：**175 篇文章、27 篇未完成标记**，所有生成页结构验证通过，内部文件与资源链接无失效项。
- 搜索集成：对真实生成 HTML 构建本地 SQLite FTS5 索引，识别并收录 **175 篇**。
- Ruff 静态检查及格式检查通过。
- 发布包的 **28 个运行依赖审计未发现已知漏洞**。旧开发环境曾返回 63 条告警记录，包含不同漏洞库的重复编号；它们不等于 63 个本项目可利用漏洞。更新依赖并为 PyPI 安装设置相应版本下限。
- HTTP 浏览器预览检查了首页、归档、草稿文章、桌面/手机与浅色/深色主题。390px 视口文章宽度约 335px，无整页水平溢出；复制按钮成功反馈已验证。

依赖审计只表示该次数据库查询未发现已知漏洞，不替代代码边界检查。Markdown 正文允许可信作者的原始 HTML；草稿仍公开发布。

## 性能实测

输入：175 篇 Markdown、556 张图片、2 个文本附件，共 733 个源文件，约 65.6 MiB。相同 Windows 主机、默认 4 工作线程，输出约 56.2 MiB，保留比旧版默认尺寸更高的图片质量。

| 构建 | 处理 / 复用 | 生成耗时 |
| --- | --- | --- |
| 更新依赖后的首轮 | 731 / 2 | 13.456 秒 |
| 修复一处文章链接后的增量 | 1 / 732 | 3.108 秒 |
| 从 PyPI 升级后的用户级 blg，全量 | 733 / 0 | 12.383 秒 |
| 同一用户级工具再次构建 | 0 / 733 | 2.669 秒 |

耗时仅覆盖生成阶段，不含打包、上传和搜索刷新；这是本机观测，不是跨设备承诺，也不是与旧版的严格对照实验。压缩等级默认 1；图片重编的成本是主要节约来源。未变化构建仍进行目录、输入/输出摘要校验和导航重建。

## 验证范围

本次没有向生产博客服务器执行迁移/部署，也没有调用线上 refresh-db。部署的命令构造、上传清理、归档拒绝、摘要验证、release 状态和失败恢复经本地测试。首次上线仍需在目标 Linux 环境核对 Python、写权限、known_hosts、Nginx 对符号链接的设置；现有站点入口路径保持不变。

搜索服务代码补丁保存在相邻项目，需要部署该服务才能让新的页面类型识别上线。常规旧文章目录仍可被原服务识别。

## 发布结果

`djhx-blogger 0.3.0` 已发布到官方 PyPI，wheel 与 sdist 的远程 SHA-256 和本地分发包一致。在独立的 uv tool 环境验证 wheel 的示例创建、构建、打包与全部内部链接后，用户级 `djhx-blogger` 从 0.2.3 升级至 0.3.0，`blg --version` 和真实全量/重复构建通过。用户的 `djhx-bilix 1.3.2` 保持不变。
